# 音色相似素材检索工具（Timbre Similarity Retrieval）

对自制短音频（关门/撞击声）计算**可解释的音色描述符**，按感知属性做近邻检索、
试听真实候选，并把检索结果用于替换影片时间轴上的关门声。全部运行时依赖为零：
仅使用 Node.js 标准库，FFT / STFT / WAV 读写 / 特征提取均为本仓库内的真实实现
（`src/dsp/`），不调用任何黑箱模型，也不读取文件名、文件大小或元信息来排序。

## 启动方式

要求 Node.js >= 18（开发环境为 Node 22），无需 `npm install`（无第三方依赖）。

**图形入口（主要使用方式）**：

```bash
cd timbre-retrieval
npm run all       # 首次：1. 生成自制音频语料 2. 提特征建索引 3. 分组评估 4. 渲染替换轨
npm run serve     # 启动界面，默认 http://localhost:8123 （PORT 环境变量可改端口）
```

浏览器打开 <http://localhost:8123>：声音分析窗口、相似排序与试听、关门声替换、
留出核对、以及**检索质量验收**都在该页面内完成。

命令行仅作辅助（分步重跑、脚本化核对）：

| 命令 | 作用 |
| --- | --- |
| `npm run build` | 模态合成 32 个短音频，写原始版与等响度版 WAV + `manifest.json` |
| `npm run index` | STFT/包络/音高分析，z-score 统计量**只在训练分组拟合** |
| `npm run evaluate` | 留组交叉验证、增益隔离实验、对照片、留出核对，输出 `data/evaluation/report.json` |
| `npm run replace` | 由检索内核为三个关门事件选首候选，混音生成替换轨 WAV |
| `npm run accept` | 辅助入口：跑一次验收门（与界面“运行验收”按钮同一逻辑），退出码 0=发布 1=拒绝 |
| `npm test` | 验收测试套件（排序质量、索引一致、受控错误） |

## 界面怎么用

- **声音分析窗口**：下拉选择查询声音（索引剪辑或**验收回归样例**），展示波形、
  对数幅度谱图、RMS 包络与 21 个实测特征值；可直接试听查询声。
- **检索控件（由同一检索内核驱动）**：检索目标（一般音色 / 道具身份 / 动作力度）、
  响度处理（等响度 / 原动态）、是否含音高块、是否含绝对响度块、距离度量（加权欧氏默认 /
  余弦备选）、是否排除同源分组。
- **结果区**：相似度排序、每个候选的真实 WAV 试听、以及“主要相似依据/差异”条
  （逐特征的 z 空间差 Δz，按贡献排序，区分频谱/包络/音高/响度块）。
- **失败反馈回检索内核**：在候选上标记“相近/不符”，提交后用 Rocchio 相关反馈在
  同一 z 空间改写查询向量并重排，而不是另起一套规则。
- **自制录音导入**：控件区可上传任意 WAV（自动转采样率/转单声道/裁静音），用与语料
  完全相同的流程提特征，并复用既有训练统计量做归一化（新片段不重新拟合任何参数）；
  导入后即成为可检索查询。分布外的声音（如纯正弦）会得到明显偏大的距离，作为
  “库中无相近素材”的信号，而不是被强行匹配。
- **关门声替换**：点击“生成替换轨”，三个关门事件经检索内核取首候选（并排除事件同源
  分组防止选回自己），混音为 `data/replacement/door_replacement.wav`；“播放替换影片”
  同步播放画布关门动画与替换轨，可下载 WAV。本环境无 ffmpeg，因此交付的是可直接
  套入视频工程的替换音轨与浏览器画面，而非封装好的 mp4。
- **评估面板**：页面底部直接展示留组指标、增益纯度、留出核对与对照片结论。
- **检索质量验收（图形入口）**：页面中的“检索质量验收”面板。点击“运行验收”即对当前
  索引版本实际**发布或拒绝**，并展示逐项证据与未通过原因；验收异常（如查询信号无效）
  也在面板中提示。下拉框中的 `q_*` 回归样例可从声音分析窗口打开：手动选择查询声音、
  试听候选，相似排序与实际素材均为实时运算（索引外查询复用训练集拟合的统计量）。

## 检索质量验收（验收器）

验收查询集与索引**分离**构建（`src/accept/queryset.js`），用来核对音色近似排序、
重复文件与无效输入：

- **同源裁片**（同一录音的时间切片）：只证明查重——裁片与源录音的波形相关系数 ≈ 1，
  且源分组须排在前列。它**不能**证明音色泛化。
- **未见演奏者的重录**（语料中从未出现的 performer 种子渲染的同类音色）：
  唯一可证明音色泛化的证据。来源在**信号层面**强制核对（与索引内任何片段的波形
  相关性必须低于阈值），因此即使把两份来源登记交换后首位命中率上升，发布断言仍会失败。
- **困难负例**（可合成）：相似包络、不同音高的正反例——整体移调 ±5/±14 半音后，
  道具类别仍须由频谱/包络决定，音高不得单独翻转类别。
- **无效输入**：静音、直流、削波、过短信号必须被拒绝并给出原因。
- **重复文件**：字节级相同的副本必须被检出，且不得重复计入证据。

期望值**独立推导**：期望类别来自 `src/accept/reference.js` 的物理参照
（模态阶梯/t60/激励参数空间），不经过检索距离函数；测试还直接守卫这一导入边界。
索引一致性（统计量重拟合、z 向量重算、特征缓存与 WAV 重算比对）由
`src/accept/consistency.js` 核对——引入错误特征缓存会使测试失败。

验收门（`src/accept/gate.js`）实际**发布或拒绝**索引版本：通过则把索引与证据报告写入
`data/accept/published/`，拒绝则清除发布目录。内置**响度统计错换诊断**：
把 eq/raw 两套响度统计交换后，检验器指出哪一类乐器的排序首先反转，
并与独立的响度子空间分析给出的预期受害者对照。

受控错误（`npm test` 覆盖）：篡改 z 向量、交换拟合统计量、丢弃索引行、
错误特征缓存、音高主导统计量——都必须被对应检查发现并拒绝发布。

## 相似性的默认定义（可验证，不宣称普适）

默认距离 = 在训练分组上拟合 z-score 后，对下列三组**音色**描述符做块加权欧氏距离：

- 频谱形状（8 个）：质心、带宽、85% 滚降、平坦度、偏度、峰度、高频能量占比、低/中频比
- 时间包络（6 个）：起振时间、衰减时间常数、包络平坦度、尾部维持比、瞬态对比、起振斜率
- 音高（3 个）：F0、置信度、非谐和度（可在界面关闭整个音高块）

**显式排除**：平均响度（rmsDb/peakDb/crestDb）与时长不进入默认音色向量，
避免“响的归响的、长的归长的”。这是信号层面的可操作定义，配合试听与量化指标供核对，
不声称任何单一距离符合所有人的听觉偏好；余弦距离作为备选可直接切换对比。

## 响度与增益：何时消除、何时保留

每个片段同时存在两套索引：

- `eq` 等响度版：全部片段 RMS 归一到同一目标电平，距离不含响度 → 前级增益差异被消除，
  适合“找同音色，不管录音电平”。
- `raw` 原动态版：保留录音电平；默认追加一个独立加权的**绝对响度块**，
  瞬态对比等动态信息因此能影响排序。界面可关掉响度块，单独隔离这一个变量。

评估报告的增益隔离实验给出 Top-5 增益纯度与同源增益孪生的平均名次：
等响度索引纯度接近 0.5（增益被忽略），原动态+响度块把同增益录音聚拢（纯度显著升高、
异增益孪生被压后），而关闭响度块后排序回到纯音色结果。

## 防泄漏与评估纪律

- 语料按“来源”分组：同一道具/力度/take 的两个前级增益版本共享一个 `group`。
- 检索与留组交叉验证都会把查询的整组从候选池排除，增益孪生或同 take 片段无法泄漏。
- 所有 z-score 均值/方差只在训练源分组上拟合一次，评估片段不参与任何调参。
- 指标：Top-1/Top-3/Top-5 命中率与 MRR，分道具身份、动作力度两个任务。
- 留出核对：4 个 `holdout_*` 片段只作查询，核对首候选的道具与力度是否正确。

## 对照实验与失败例

- **不同音高、相近音色**（`ctl_pitch_*`）：整体移调 5–7 半音，同道具片段仍应排在前列。
- **相同音高区、不同发声方式**（`ctl_rub_*`）：指尖摩擦替代敲击，起振/包络大变，
  不会出现零距离的敲击孪生，但同道具身份仍可在前列恢复——用于展示“音高对、方式错”
  时排序如何变化。
- 失败例与每个对照片的完整排序保存在 `data/evaluation/report.json`（`failures`、`controls`）。

## 目录

```
src/dsp/      wav 读写、FFT/STFT、特征提取、模态合成、响度处理
src/core/     距离度量、索引、检索/Rocchio、分组评估、替换轨混音
src/accept/   验收器：分离查询集、独立物理参照、一致性核对、发布/拒绝门
src/cli/      命令行入口（build/index/evaluate/replace/all/accept，均为辅助入口）
src/server/   零依赖 HTTP 服务与 API（含 /api/accept/* 验收路由）
web/          图形入口：分析窗口、检索结果、替换影片、评估面板、验收面板
test/         验收测试（排序质量、索引一致、受控错误；node --test）
data/         运行后生成（语料、索引、报告、替换轨、验收发布），已 gitignore
```

文件名全部使用中性 ID（`c_P1_light_t0_hi` 等），不含乐器/道具词；检索代码也不解析
文件名，道具词只存在于 `manifest.json` 的真值字段中供评估使用。
